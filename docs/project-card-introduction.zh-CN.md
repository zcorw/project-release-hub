# 项目卡片简介

[English](project-card-introduction.md) | [简体中文](project-card-introduction.zh-CN.md)

## 已确认需求

知序任务 `84ddc9b8-cddd-4b87-9dab-7b825f093976` 要求：首页项目名称下方显示项目简介，不显示任务日志、提交、测试或部署更新，同时保留已有历史与进度信息。

## 实现决策（2026-11-17）

- 为项目添加独立的 `summary` 字段，去除首尾空白后最多 500 个字符，通过已有的 Web/API/MCP 共享契约编辑。这是为了将简介与现有多用途 `description` 区分而选定的实现默认方案。
- 卡片只显示 `summary`，为空时显示“暂无项目简介”。不通过截断或过滤历史说明猜测简介。
- 保留 `description`、任务与问题、进度、审计快照和请求载荷。项目详情继续展示完整说明。
- 传输契约中该字段保持可选，确保历史请求哈希不变。旧客户端更新时省略该字段会保留已有简介；显式发送空字符串可清空。历史项目在明确填写前保持空简介。本次不回填生产数据。
- 保留现有 Web 提案与确认、MCP 授权、修订号、重放和撤销规则。不需要新增服务或数据库表。

## 验证与交付

验证通过：`npm run check`（格式、严格 TypeScript 检查、18 个文件中的 178 项单元/集成测试及生产构建）与 `npm run test:e2e`（18 个 Chrome 场景，其中包含三个新增的真实后端简介流程）。覆盖历史数据持久化、请求重放与更新、显式清空、校验、审计、撤销、提案协调、真实 HTTP/MCP 读写，以及保留进度和窄屏布局的浏览器卡片、编辑与详情流程。桌面/移动端截图和独立差异审查通过。旧客户端提案预览现在与实际更新一致，展示保留的简介。

Windows 检出最初将未改动的源文件转换为 CRLF，导致 Prettier 阻止检查。仓库属性现将文本保留为 LF，其余未改动文件没有语义变化。首次沙箱内浏览器运行停在本地服务启动阶段，已停止；授予临时本地进程/网络权限后完整检查通过。测试使用隔离数据库，没有使用生产数据。
