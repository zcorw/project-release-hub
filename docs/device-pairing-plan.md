# Isolated device pairing integration

This code-stage increment joins pairing, explicit owner approval, scoped report reads, renewal and unbinding. It remains unmounted in production. Tests use synthetic accounts and injected owner authentication/CSRF guards; no live credentials or settings are created.

Delegated defaults: pair requests expire after five minutes; device secrets and renewal secrets are 256-bit random values, stored only as hashes. Owner approval names an exact device request and nonempty project selection. Claim is retryable within its five-minute deadline using only the secret device code. It returns a renewal secret derived with server-only replay material but no report access. The device must save that secret then explicitly confirm; unconfirmed bindings expire five minutes after their first claim. Lost claim and confirmation responses are safely retryable across restart. A confirmed binding cannot be claimed again and its server replay material is erased; the original device secret alone cannot derive a renewal credential. Renewal is bounded to 30 days and cannot expand the approved project set. A stable renewal secret avoids a lost rotation response stranding a device. Unbinding and account password-version changes invalidate all related access and renewal. This is not push transport or a production OAuth server.

The router factory requires an explicit trusted owner-write guard. The production integration must supply authenticated session plus CSRF validation, HTTPS and reviewed proxy/rate-limit behavior before mounting. The isolated router limits lifecycle requests to 30 per minute per source IP; production also needs durable quotas and an approved expired-record retention policy, not implemented here. Browser consent UI and secure device-side credential storage still require implementation and review. The report payload remains the existing minimized schema; it does not infer the unresolved owner-action widget filter.
